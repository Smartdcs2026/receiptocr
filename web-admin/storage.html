สถานะ D1 ↔ R2

D1 เก็บดัชนีและ object key ส่วน R2 เก็บไฟล์จริง ระบบสามารถตรวจและซ่อมความเชื่อมโยงได้โดยไม่ใช้ลิงก์สาธารณะ
-
รายการภาพใน D1
-
ไฟล์งานจริงที่ D1 ติดตาม
-
งานที่ยังส่งภาพไม่ครบ
-
ดัชนีภาพที่หาไฟล์ใน R2 ไม่เจอ*
ยังไม่ได้ตรวจสถานะ D1 ↔ R2
* ตรวจตัวอย่างรายการภาพล่าสุดสูงสุด 100 รายการต่อครั้ง

วินิจฉัยภาพที่ยังไม่เชื่อมโยง

Round104.4 แสดงงานที่หลักฐานยังไม่ครบและไฟล์ R2 ที่ระบบไม่สามารถผูกกับ Submission อัตโนมัติได้ เพื่อให้ Admin ตรวจภาพและผูกเองอย่างมี Audit
-
งานที่หลักฐานยังไม่ครบ
-
ไฟล์ R2 ที่ยังไม่ผูกงาน
งานที่หลักฐานยังไม่ครบ — ใช้เทียบกับหน้า “ศูนย์ตรวจสอบงาน” ว่างานใดไม่มีภาพบิลหรือภาพร้านจริง
Submissionร้านวันที่ / พนักงานบิล / ร้านเงื่อนไขสถานะ
กำลังโหลด...
ไฟล์ R2 ที่ยังไม่ผูกงาน — กด “ดูภาพ” ก่อน แล้วเลือก Submission ที่ถูกต้อง ระบบจะไม่เดาให้ถ้ามีหลายงานที่เป็นไปได้
ภาพObject keyข้อมูลจาก R2งานที่เป็นไปได้ประเภท / ลำดับ
กำลังโหลด...
การผูกแบบ Manual จะบันทึก Audit ทุกครั้ง และจะไม่ทับ slot ที่มีภาพอยู่แล้ว หากเลือกงานหรือประเภทภาพผิดให้ยกเลิกก่อนกดยืนยัน

การใช้พื้นที่ R2

หน้านี้นับไฟล์ที่ ReceiptOCR ติดตามใน D1 หากมีไฟล์เดิมใน R2 ให้กด “ตรวจนับไฟล์ R2”
-
ใช้ไปแล้ว
-
โควต้าพื้นที่ฟรีที่ใช้เป็นเป้าหมาย
-
จำนวนไฟล์
-
ไฟล์ที่ป้องกันการลบ
-

นโยบายพื้นที่จัดเก็บ

การตั้งค่านี้ใช้สำหรับเตือนและควบคุมภายในระบบ ไม่ได้ตัดการใช้งาน Cloudflare โดยอัตโนมัติ

เคลียร์ D1 + R2 จาก Admin

ลบเฉพาะข้อมูลงานที่ส่งและภาพงานจริง ไม่แตะแผนงาน, ผู้ใช้, กฎ OCR, โลโก้ หรือภาพ Training
ยังไม่ได้ตรวจจำนวน
ระบบจะลบไฟล์ R2 ก่อน แล้วจึงลบดัชนีภาพ/POS/Submission ใน D1 หาก R2 ลบไม่สำเร็จ รายการนั้นจะถูกข้ามเพื่อไม่ให้ D1 สูญเสียตัวอ้างอิง
